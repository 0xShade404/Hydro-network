# Verifier

`contracts/TransferValidityVerifier.sol` is **generated**, not hand-written
— `zk/circuits`' compile step calls ZoKrates' `exportSolidityVerifier()`
and writes it here (see `zk/circuits/README.md`). It's a standard
Groth16 pairing-check verifier (Christian Reitwiessner's widely-used
template, MIT licensed) using Ethereum's `ecAdd`/`ecMul`/`ecPairing`
precompiles — no custom cryptography written for this project, per
`CLAUDE.md`'s rules.

The contract's public entry point:

```solidity
function verifyTx(Proof memory proof, uint[5] memory input) public view returns (bool r)
```

`zk/prover`'s `formatProofForContract()` converts a ZoKrates proof into
this exact shape.

This directory is gitignored except `package.json` and this README's
supporting files — the contract and its compiled artifacts are build
output. Run `npm run compile:zk` (from repo root) before anything here.

## Security

Same caveat as `zk/circuits`: the verifying key baked into this contract
came from a local, non-ceremony Groth16 setup. It's fine for demonstrating
the pipeline; don't deploy it anywhere real value depends on it without
redoing the setup properly.

## Usage

```bash
npm install                       # from repo root
npm run compile:zk                 # generates the Verifier contract
npm run test:zk-verifier           # compiles it and runs its tests
npm run node:dev                   # separate terminal: local devnet
npm run deploy:local --workspace=zk/verifier
```

## Testing

`test/Verifier.test.ts` deploys the compiled contract to Hardhat's
in-process network (no live node needed) and calls `verifyTx` with a real
proof generated by `@hydro/zk-prover`:

- a genuine proof of a valid transfer is accepted;
- the same proof with a tampered public input is rejected;
- a proof for one transfer is rejected against a different transfer's
  public inputs.

This exercises the real cryptographic verification path (elliptic-curve
pairing checks via the EVM precompiles), not a mock.
